# ADR-0017: Costed Persistent Development in a Separate Protocol

- Date: 2026-11-19
- Decision status: Accepted

## Context

ex5 demonstrated dynamic resource declarations but exposed single-resource site allocation, unsupported intermediate effects, inadequate realized supply and no enduring improvements to daily work. The authorized next task combines development goals with skills/resources/facilities, while retaining the working task and delivery framework and historical protocols.

## Decision

Add coevolution-v1 and replay/archive version6, with its own pure typed interpreter and immutable configuration. Reuse foundation movement, finite schema utilities, the OAuth transport, existing task handoff pattern and shared archive viewer. Keep the earlier evolution implementation unchanged to preserve exact replay. Costed persistent objects affect carrying/rest; declared recipes consume inputs before delayed shared outputs; three stable finite ecological slots permit coexistence without request-driven rerolls. Individual mastery, project self-report and measured benefit are distinct.

The runner uses existing conversation development barriers, total attempt budgets, durable before-call records and staged snapshots. Exhaustion produces a globally frozen observation window, which may be fully archived without claiming the target horizon completed. Internal conversation model usage cannot be metered; cap development interventions and disclose the gap. No second coding agent or recursive service is introduced.

At the first real barrier, cultivation needed an executable effect beyond the initial declarative envelope. A narrow versioned source bridge retains both engine snapshots and verifies the complete existing execution/call prefix before accepting a current-conversation interpreter extension. It permits only coevolution effect files, freezes base parameters/carrying/rest and every simulator file, and runs full unit/type/lint/architecture/build checks. The first extension is bounded photosynthetic production on costed stationary objects, using existing pickup for shared harvest. This is an explicit world-extension version, not a hidden base adjustment or a restarted sample.

## Alternatives and reasons

Prompt-only changes would describe capabilities without physical effects. Rewriting evolution-v1 would change ex5 evidence. Refactoring the working harness or generalizing every old protocol would expand scope and compatibility risk; version-specific modules and narrow routing/display additions are easier to review. Unrestricted generated JavaScript would undermine deterministic conservation and source-bound resumption. A bounded effect language supports useful new compositions without granting arbitrary host execution.

## Costs and future consequences

Separate protocol modules duplicate some earlier transition/scheduling structure. The physical envelope, three ecological slots, bounded bonuses and recipe conservation are deliberate finite approximations. Natural plausibility and broad functional equivalence still require semantic judgment. Two related mechanisms changing together cannot establish either one's causal effect. Any required base change during a run needs a retained original and a new version/run. Future extraction of shared code should follow demonstrated stability as a separately scoped task.
