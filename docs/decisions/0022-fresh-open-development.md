# ADR-0022: Experiment-Scoped Cumulative Development

Date: 2026-11-21

Status: Accepted

## Context

Ex9 inherited six ex8 packages and accumulated detailed context until several
input protection pauses. Its genuine later capabilities and execution repairs
should remain replayable, but a fresh inquiry must not present those capabilities
as independently discovered. Existing task barriers, reference resolution and
operation bindings already work and should remain shared infrastructure.

## Decision

Use an immutable development policy and explicit authored baseline. Filter the
registry by experiment scope and independently guard installation. Retain all
historical source while initializing no generated state, catalogue or mastery.
Same-world publication and individual study remain separate transitions.

Persist actor-selected projects and evidence-qualified knowledge. Bound views,
not retained records; use on-demand record and capability details. Settle trials,
practice and reciprocal participation in deterministic event rules. Separate
claims, relations and physical facts. Add conditional local ecology and a costed
persistent-process helper with conserved input/output provenance; reviewed
packages still implement new mechanisms through the current conversation.

Use the existing continuous replay, scoped validation and PR workflow. New
behavior is selected only by `config.development`; old transitions are preserved.
Formal policy freezes before first inference. See [protocol](../OPEN_DEVELOPMENT.md)
and [execution plan](../exec-plans/active/pr-24-open-development.md).

## Alternatives

Clearing only mastery leaks old functions into search and prompts. Reusing old
packages silently supplies mature routes. Prompt-only curiosity does not establish
physical trials or persistent processes. A fixed technology tree preselects
outcomes. Replacing the working harness duplicates durable state and validation.

## Consequences

A fresh survival preflight cannot use historical warming or other generated
skills. Equivalent new requests require new review and learning; any implementation
reuse needs source attribution. Bounded contexts cost explicit lookup actions.
Local plant/animal dynamics are simplified accelerated models. Trusted generated
code still requires real review, conservation tests and visual evidence. Longer
runs retain state but remain subject to explicit computational and inference
budgets. The experiment measures early evidence, not guaranteed civilization.

Reviewed package responses may run after environmental events and before
death/drop processing. Only installed packages run; the same protected-rule,
mastery, life and wellbeing-account fingerprint used for processes guards these
responses. This supports real fragile-object consequences without allowing
background historical skill effects or direct reward-account mutation.

Generic transformation contracts must retain prior escrow metadata. Once an
input has represented physical mass, water and solids, outputs must explicitly
conserve each quantity. A catalogue mass default cannot erase measured state;
undeclared transformations fail before allocation.
