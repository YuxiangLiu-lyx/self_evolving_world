## Current observations and discrepancies

The current harness command is only an alias for validate; it does not currently control the surrounding conversation, commit or PR preparation. Both code and documentation route as code; only numbered artifacts plus numbered plan files qualify as experiment-only. The existing publisher supports HTTP publication/merge and a prepare-only/connector/verify-only path; this migration uses that existing connector path for merge handoffs. It retains the 90-attempt, ten-second CI polling limit and existing HTTP timeouts.

The checked-out AGENTS and delivery code default to merge based on the earlier standing instruction. The user-supplied guide also says never merge without explicit instruction; the current task independently prohibits merging this PR. Preserve the existing code default while requiring a separately evidenced applicable grant, with task exceptions taking precedence. This task explicitly forbids merge, so its changed plan records PR-only delivery. A granted authorization field is a record of an actual instruction, not a capability that software may invent. A future task with no evidenced grant must stop before merge even if publication is green.

The general prose describes reviewed commits for tasks, but the existing local-only final path accepts a reviewed dirty worktree and performs no network calls. Preserve that actual exception behavior; do not add a commit requirement. Explicit reuse is allowed by archive-preservation policy, while experiment:resume itself only repairs incomplete capture and refuses completed records. Preserve this distinction: no automatic completed-record overwrite. Existing reports primarily contain execution metrics and protocol limitations, not a systematic per-agent semantic analysis. R9 intentionally adds that requested analysis without redefining execution success or the ex2 pickup criterion.
